# HelmetGuard 2.0.1 修复说明

本次针对首轮真机反馈集中修复扫描、权限、事故流程和升级兼容问题。

## BLE 扫描

- 权限授权完成后自动继续原操作，不再发生“首次点击扫描只弹权限、但实际没有开始扫描”的竞态。
- 扫描前主动停止旧扫描，避免部分 ROM 返回 `SCAN_FAILED_ALREADY_STARTED`。
- 不再只展示名称以 `HelmetGuard` 开头的结果：兼容头盔优先显示，同时保留附近其他可连接 BLE 设备，便于诊断广播名或服务 UUID 配置错误。
- 支持无设备名但广播 FFF0 服务的头盔，显示为“HelmetGuard（未命名）”。
- 显示兼容标记、可连接状态、RSSI 强度和更明确的扫描失败原因。
- 扫描为空时显示供电、距离、权限、Android 旧版本定位总开关和蓝牙重启步骤。
- 只有完成 GATT 服务发现与通知订阅并达到 `READY` 后才持久化绑定，避免误点其他 BLE 设备导致下次自动连接错误对象。
- 增加“忘记旧设备并重新绑定”和系统蓝牙开启入口。
- Companion Device 关联不再同时强制名称与服务 UUID，兼容把服务 UUID 放在 scan response 的旧固件。
- ESP32-S3 固件显式设置广播名称。

## 事故事件与闪退防护

- 前台服务启动改为安全调用；系统禁止启动时通过 Snackbar 显示错误，不再让 Activity 因未捕获异常退出。
- 事故倒计时、定位、短信等整个处理链增加顶层异常隔离；异常会把事件落为 `FAILED` 并给出手动求助提示，不会留下永久卡住的活动事件。
- 通知发送增加异常防护。
- 历史事故坐标仅在经纬度同时存在时格式化，兼容不完整或旧数据。
- 待恢复事故阶段使用安全解析，异常数据不再直接触发 `valueOf` 崩溃。
- 运行时权限拒绝、配套设备关联取消和服务启动失败均提供可见反馈。

## 数据库升级

2.0.0 早期测试包到 2.0.1 增加了 `batteryValid` 字段。本次将 Room 数据库升级到版本 2，并提供 `1 → 2` 非破坏迁移，保留联系人、事故历史和实验记录，避免升级安装后的 schema 校验崩溃。

## 版本

- `versionCode`: 21
- `versionName`: 2.0.1

如果事故入口仍发生闪退，需要同时提供：手机品牌/型号、系统版本、操作入口（手动求救、模拟碰撞或历史事故标签）以及 `adb logcat` 中 `FATAL EXCEPTION` 前后的日志。不同入口的 Android 系统限制并不相同。
