# HelmetGuard 2.0 测试与发布门槛

## 自动测试

- BLE：CRC 固定向量、分片、粘包、垃圾前缀、坏 CRC 后恢复、工程单位解析、命令兼容。
- 检测：正常骑行不触发、减速带排除、未佩戴掉落排除、事故波形触发、时间断流复位。
- 数据：Room 外键级联、记录通道留空、批量落库、CSV 转义和会话计数。
- 事故：倒计时取消、立即求救、进程恢复、模拟隔离、无权限和无联系人失败路径。
- 短信：双卡未选时阻断、分段唯一 PendingIntent、提交/送达独立聚合、超时和部分成功。

运行：

```bash
./gradlew testDebugUnitTest
./gradlew connectedDebugAndroidTest
./gradlew lintDebug
./gradlew assembleRelease
```

## 硬件矩阵

至少覆盖：华为 HarmonyOS 4、荣耀 MagicOS、小米/Redmi MIUI 或澎湃 OS、OPPO/一加 ColorOS、vivo/iQOO OriginOS、三星 One UI；每类至少一台 Android 12+，华为必须用无 GMS 环境。

每台设备执行：

1. 单卡、双卡有默认项、双卡无默认项。
2. 屏幕亮/灭、App 前台/后台、从最近任务划掉、锁定任务、重启手机。
3. 蓝牙断开重连、超出范围后返回、关开蓝牙、ESP32 重启、通知分片与丢包。
4. GPS 室外、网络定位室内、关闭定位、仅旧位置、定位超时。
5. SMS 正常、无信号、飞行模式、欠费/停机卡（若测试条件允许），验证 sent 与 delivery 分离。
6. 通知权限关闭、电池优化开启、自启动关闭，确认可靠性中心明确告警。
7. 倒计时通知在锁屏可见，两个 action 正常，取消后绝不发送。
8. App 进程在倒计时中被杀后重启，事件和 deadline 可恢复。

## 算法数据集

每种头盔安装方式至少记录：

- 10 小时以上正常道路骑行；
- 多种速度、角度的减速带/坑洼各 100 次；
- 急刹、上下车、手持、桌面取放各 100 次；
- 不同地面和高度的未佩戴掉落（仅设备）各 50 次；
- 由专业夹具/假人完成的受控碰撞测试。

发布报告必须列出每类混淆矩阵、每骑行小时误报数、数据缺失率和设备型号。不得用模拟波形替代全部实测。

## 发布阻断项

- 任意模拟流程可能调用真实短信或定位。
- API 调用无异常就标记短信成功，而未等待 SENT 回执。
- 双卡不明确仍静默选择错误 SIM。
- 服务通知可被代码隐藏但仍声称后台监测。
- Release 使用 debug 签名、明文联系人日志或允许系统备份。
- 无 HarmonyOS 4 真机、锁屏、重启和进程恢复测试证据。
- 未完成受控真实数据标定却宣传“零误报”或“医疗级”。
