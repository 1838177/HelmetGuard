# 多阶段事故检测与标定

## 设计目标

HelmetGuard 2.0 不再采用“加速度超过一个阈值就报警”。检测过程分为：

1. **IDLE**：保留约 2.5 秒碰撞前窗口。
2. **OBSERVING（1.2 秒）**：计算冲击峰值、角速度峰值、姿态变化、自由落体和碰撞前运动背景。
3. **VERIFYING_STILLNESS（3.5 秒）**：计算碰撞后合加速度方差和角速度 RMS。
4. **COOLDOWN**：产生一个持久化事故候选，交给倒计时和求救协调器。

默认阈值位于 `DetectorConfig`，不是医学结论，也不是所有头盔安装方向的通用值。

## 默认判据

- 候选冲击：`>= 3.2g`；强冲击：`>= 5.8g`
- 显著角速度：`>= 220°/s`
- 显著姿态变化：`>= 38°`
- 自由落体：合加速度 `<= 0.35g`，持续 `>= 80ms`
- 碰撞后静止：加速度方差 `<= 0.075` 且角速度 RMS `<= 18°/s`
- 综合触发分：`>= 0.66`

强冲击、旋转和姿态是主要权重；自由落体只是辅助证据，不能单独触发。

## 误报抑制

### 减速带

中等冲击但角速度低于 115°/s、姿态变化小于 16° 时，识别为短垂直脉冲并排除。急刹车和坑洼仍需真实采样标定。

### 未佩戴头盔掉落

以下特征同时成立才倾向排除：碰撞前长期极静止、存在自由落体、冲击未达到强冲击阈值、碰撞后达到近乎完全静止。该规则避免简单桌面跌落触发，但不能证明头盔是否有人佩戴。

**正式硬件强烈建议添加佩戴传感器。** 单 MPU6050 无法从物理上区分“静止的人遭碰撞后失去意识”和“静置头盔掉落”，两者可能具有相同 IMU 波形。

## 数据质量

- 相邻样本时间倒退或间隔超过 500ms 时立即复位候选，禁止拼接陈旧波形。
- BLE CRC 错误帧直接丢弃，序号跳变累计为疑似丢帧。
- IMU unhealthy 或未校准帧不启动新候选。
- 推荐固定安装方向、20–50Hz、严格记录真实采样时间。

## 标定流程

1. 在安全封闭场地选择要记录的参数。
2. 分别标注正常骑行、减速带、坑洼、急刹、取放头盔、低高度掉落和受控碰撞。
3. 导出 CSV，按**人和骑行批次**划分训练/验证集合，不能随机打散相邻帧造成数据泄漏。
4. 优先观察漏报，再控制误报；分别报告每类场景的召回率、精确率和每骑行小时误报数。
5. 修改 `DetectorConfig` 后重放同一批固定数据进行回归。
6. 不允许真人故意摔车采集。碰撞实验使用假人、测试夹具和专业人员。

CSV 可包含原始三轴、合量、姿态、设备状态和每帧检测特征；用户未选择的通道存储为留空，避免暗中收集。
