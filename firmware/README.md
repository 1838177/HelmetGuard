# HelmetGuard ESP32-S3 参考固件

该固件与 Android 2.0 的 FFF0–FFF3 协议直接兼容，面向：

- ESP32-S3-DevKitC-1
- GY-521 / MPU6050
- 3.3V 有源蜂鸣器
- 常开微动按键
- 单节 18650/锂电池 + 带保护 TP4056

## 接线

| 模块 | ESP32-S3 默认引脚 | 说明 |
|---|---:|---|
| MPU6050 VCC | 3V3 | 禁止接 5V 后再把 I²C 上拉到 5V |
| MPU6050 GND | GND | 共地 |
| MPU6050 SDA | GPIO 8 | 可在 `include/BoardConfig.h` 修改 |
| MPU6050 SCL | GPIO 9 | 400kHz |
| 微动按键 | GPIO 4 ↔ GND | 使用内部上拉，低电平按下 |
| 有源蜂鸣器控制 | GPIO 5 | 仅适用于低电流 3.3V 蜂鸣器 |
| 电池采样 | GPIO 1 | **必须先经过分压，默认未启用** |

若蜂鸣器工作电流超过 ESP32 GPIO 的安全能力，必须使用 NPN/NMOS 管、基极/栅极电阻和正确的电源设计，不能直接驱动。

### 电池测量

TP4056 通常不提供可直接读取的电量百分比。锂电池最高约 4.2V，**绝不能直接接 ESP32 ADC**。若要启用电量：

1. 电池正极 → 100kΩ → ADC 节点 → 100kΩ → GND；
2. ADC 节点并联约 100nF 到 GND；
3. 确认满电时 ADC 电压不超过芯片允许值；
4. 将 `HG_HAS_BATTERY_DIVIDER` 改为 `1`，按实测校准分压比和空/满电压。

未配置安全分压时，固件上报 0%，并清除“电量有效”状态位，不会伪报满电。

## 编译与烧录

安装 VS Code + PlatformIO，或使用命令行：

```bash
cd firmware
pio run
pio run --target upload
pio device monitor
```

首次启动时将进行约 1.2 秒陀螺仪零偏校准，请保持头盔静止。设备广播名类似 `HelmetGuard-S3-A1B2`。广告中的 FFF0 使用 16 位 UUID 编码，Android 会自动展开为 Bluetooth Base UUID；名称放在 scan response，避免 31 字节广告容量不足。

## 行为

- IMU 50Hz 采样，BLE 25Hz 遥测；量程为 ±16g、±2000°/s。
- 手机完成 FFF1/FFF2 CCCD 订阅后接收遥测和事件。
- 物理按键：单击上报、双击请求立即求救、长按取消当前警报。
- 手机“响铃查找”命令触发短时蜂鸣；事故报警优先级更高。
- 事故事件每秒重发直到收到相同 `eventId` ACK；取消命令关闭蜂鸣。
- 事件号存入 NVS，仅每次事故写一次，避免逐帧损耗 Flash。
- 看门狗在主循环和校准期间持续喂狗。

## 检测边界

固件侧检测只是手机断连/异常时的降级保护；连接正常时，以 App 的多阶段算法和记录数据为主要判断依据。单个 MPU6050 不能证明头盔已佩戴，正式硬件必须增加佩戴传感器并完成受控标定。

严禁把面包板、裸露锂电池、无保险 TP4056 或未经固定的杜邦线直接用于道路骑行。正式样机需要合规 BMS、保险、结构固定、防水、EMC 和电池安全验证。
